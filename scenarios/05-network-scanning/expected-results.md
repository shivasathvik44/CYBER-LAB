# Scenario 05: Expected Results & Network Scan Telemetry

This document details expected Suricata NIDS alerts and firewall connection logs generated by the network scanning simulation.

---

## 1. Expected Suricata Alert Output (`eve.json`)

When an attacker node executes rapid port sweeps, Suricata rule `1000001` matches the threshold conditions:

```json
{
  "timestamp": "2026-11-14T12:45:10.104231+0000",
  "flow_id": 140293810293,
  "event_type": "alert",
  "src_ip": "172.20.0.99",
  "src_port": 49210,
  "dest_ip": "172.20.0.30",
  "dest_port": 80,
  "proto": "TCP",
  "alert": {
    "action": "allowed",
    "gid": 1,
    "signature_id": 1000001,
    "rev": 1,
    "signature": "HOMELAB SCAN Potential Nmap Scripting Engine or SYN Sweep",
    "category": "Attempted Information Leak",
    "severity": 2
  }
}
```

## 3. SOC Analyst Triage Checklist
- [ ] Determine if the scanning source is an authorized vulnerability scanner or rogue IP.
- [ ] Check if any scanned ports responded with `SYN-ACK` (open state).
- [ ] Correlate source IP with follow-up exploitation attempts (e.g. Scenario 01 or Scenario 04).
